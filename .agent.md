# MTP Weaver Agent Contract

This repository is a kernel-contract and mission-regression repository. Any coding assistant working here must preserve the `kernel -> core -> mission` contract path and keep all execution fail-closed.

## Required Read Order

Before proposing or generating code, read these in order:

1. `README.md`
2. `KERNEL_CONTRACT.md`
3. `run_kernel_contract_checks.py`
4. `tests/test_kernel_contract.py`
5. The relevant file under `core/` or `missions/`

Do not start from implementation files alone and infer the contract afterward.

## Repository Rules

- Treat `KERNEL_CONTRACT.md` as the governing boundary for runtime behavior.
- Keep `kernel -> core -> mission` execution explicit and fail-closed.
- Preserve append-only and audit-oriented semantics when touching runtime code.
- Do not introduce warning-only paths, hidden retries, or silent degradations.
- Do not change kernel behavior without updating the regression path that proves it.

## Required Change Protocol

When changing the effective runtime contract, update all relevant layers together:

1. `KERNEL_CONTRACT.md`
2. `run_kernel_contract_checks.py`
3. `tests/test_kernel_contract.py`
4. The affected file under `core/` or `missions/`

If a change is UI-only or documentation-only, do not claim contract changes that are not backed by the regression path.

## CI Expectations

Local validation entrypoints are:

- `python tools/ci_gate.py validate-kernel-contract`
- `python tools/ci_gate.py validate-mission-regression`
- `python tools/ci_gate.py validate-governance`
- `python tools/ci_gate.py unit-tests`

All gates are binary. The only valid outcomes are `PASS` or `FAIL`.

## Preferred Agent Behavior

- Start by identifying which kernel guarantee is affected.
- Make the smallest change that preserves fail-closed execution.
- Prefer extending the existing regression path over inventing a parallel validation path.
- If a request is ambiguous, choose the stricter audit-preserving interpretation.

## Forbidden Patterns

- Contract changes without regression updates
- Silent fallback when kernel collaborators are missing or malformed
- Ad hoc error handling that weakens fail-closed behavior
- Treating mission success as sufficient if the documented kernel guarantees no longer hold

## Definition of Done

A change is not complete until:

- `KERNEL_CONTRACT.md` still matches the implemented kernel path
- the kernel regression path passes
- unit tests cover the changed behavior
- `tools/ci_gate.py` passes for all required gates
